## 决策记录

### ADR-001：不用 iframe 承载游戏

- 背景：iframe 是移植现有 HTML5 游戏最省事的办法。
- 决策：不用。游戏必须是模块，跑在同一个 DOM 里。
- 理由：iframe 拿不到主题、locale、指针上下文；官方实践不建议；还会让「窗口」变成两层页面。
- 代价：移植要改入口代码，不能直接贴 URL。

### ADR-002：先定运行时契约，再写游戏

- 决策：`mount / resize / pause / resume / destroy` 五件套 + `definition` 元数据，所有适配器归一到这层。
- 理由：窗口和内嵌舞台共用一套生命周期；先定契约，后面加游戏不用改窗口。
- 代价：契约没稳定前，第一个游戏要跟着契约调。

### ADR-003：接受「无法拖出 DSH」

- 背景：用户要求窗口能拖到桌面上。
- 核查：DSH 桌面壳的 Web/Host 跑在 Electron 子进程里，只有主进程能开 `BrowserWindow`；壳没有向插件开放开窗 IPC；主窗口的 `setWindowOpenHandler` 也拒绝 `window.open`。
- 决策：不硬做。用户已选方向 B（宿主提供独立窗口能力），插件侧需求与接入方案见 [DETACH.md](DETACH.md)，能力到位后只补一个渲染分支。
- 影响：当前自由窗用应用内浮窗顶着；等宿主。

### ADR-004：半屏是覆盖式吸附

- 决策：左/右半屏 = 浮窗贴边覆盖，不做真正的布局重排。
- 理由：插件拿不到聊天列宽度，无法让宿主让位。
- 代价：半屏会盖住聊天的一部分，默认给输入框留空。

### ADR-005：存档先放 Host，不放 localStorage

- 决策：游戏分数/进度走 `host.call` 存到 Host 侧；窗口位置这种 UI 状态可以放 localStorage。
- 理由：Web 端口变化会让 localStorage 失效；存档比窗口位置重要。

### ADR-006：游戏代码默认可信

- 决策：只加载随插件发布的模块，不做「输入网址装游戏」。
- 理由：同页面执行权限，无法沙箱化；审查比事后限制便宜。

## 风险

| 风险 | 影响 | 缓解 |
|:--|:--|:--|
| DSH alpha 插槽变动 | 页面/入口失效 | 只用公开槽位；升级后跑验证清单 |
| 跨 bundle 注册未验证 | 第三方游戏包无法接入 | M3 前先做 spike，失败则退回「游戏中心内置收录」 |
| Ruffle 体积 / CSP | Flash 适配器不可用 | 按需加载 + 失败降级为说明卡 |
| 自定义视频背景体积 | 卡顿 / 存储超限 | 限制大小、放 IndexedDB、失败回退极光 |
