# 窗口模型

> 状态：**内嵌 / 悬浮两种模式已实现**；「拖出 DSH」经核实不可行，见第 5 节。

## 1. 两种模式

| 模式 | 默认 | 行为 |
|:--|:--|:--|
| **内嵌（embedded）** | 是 | 游戏渲染在游戏中心页面里：左侧抽屉放游戏列表，右侧是舞台。不占额外浮层。 |
| **悬浮（floating）** | 否 | 游戏进入独立浮窗，从右侧滑入；可拖拽、八向缩放、吸附左右半屏或全屏。 |

## 2. 切换

- 内嵌 → 悬浮：**双击舞台标题栏**，或点标题栏的「⋯ → 悬浮窗」。
- 悬浮 → 内嵌：**双击浮窗标题栏**，或点浮窗标题栏的「内嵌」。
- 关闭：舞台 / 浮窗标题栏的 ×，回到游戏中心首页。
- 换游戏：抽屉里点另一款；浮窗开着时，抽屉换游戏会直接替换浮窗内容。

## 3. 布局

```
游戏中心页面
├─ 背景层（极光渐变，可后续换自定义图片/视频）
├─ 标题栏（标题、副标题、窗口设置入口）
└─ 游戏视图
   ├─ 左侧抽屉（游戏列表，可折叠，玻璃质感）
   └─ 舞台
      ├─ 舞台标题栏（抽屉开关、游戏名、⋯、关闭）
      └─ 游戏容器（自适应尺寸，圆角 + 阴影）
```

悬浮窗从右侧滑入，**不接管聊天布局**：它浮在页面上方，游戏中心页面留在后面，左侧抽屉仍可操作（换游戏）。因此「主界面保留一部分功能」靠抽屉实现。

**内嵌舞台占满可用高度**：进入游戏视图后页面收窄头部（标题变小、副标题隐藏），舞台高度为视口高度减去头部，抽屉 232px，游戏区域尽量大。

**动效**：页面 → 内嵌舞台从右侧滑入（300ms）；窗口收回 / 关闭时向右淡出（180ms），舞台内容再淡入（220ms）。

## 4. 拖拽 / 缩放 / 吸附

- 拖拽：标题栏；拖动超过 4px 才算拖动，避免误触。
- 缩放：四边 + 四角，最小 320×240。
- 吸附：拖到距屏幕边缘 16px 内松手，自动贴边；双击标题栏在全屏/浮窗之间切换。
- 半屏：左半屏、右半屏；默认给底部输入框留 84px，可关闭。
- 位置、尺寸、模式、抽屉开关持久化（localStorage），重启恢复。

## 5. 「拖出 DSH」——结论：当前做不到

**现象**：游戏窗口只能待在 DSH 窗口内部，拖不到桌面上。

**原因**（已核对本机 0.2.3-alpha.2 的桌面壳）：

- DSH 的 Web 页面和插件都运行在 Electron 的**子进程**里（`spawn` 出的 `dsh-desktop-host`），不是 Electron 主进程。
- 只有主进程能 `new BrowserWindow` 创建系统窗口；插件进程拿不到这个能力。
- 桌面壳没有向插件开放「开新窗口」的 IPC；子进程发过去的消息只接受固定的几种内部事件。
- 主窗口的 `setWindowOpenHandler` 直接拒绝弹窗（http/https 只交给系统浏览器），所以也没有 `window.open` 这条捷径。
- 客户端插件更是只能操作页面 DOM，连尝试的入口都没有。

所以这不是实现问题，是**宿主没有提供这个扩展点**。硬做需要改 DSH 桌面壳（加一个「插件页在新窗口打开」的能力），不属于插件能解决的范围。需求与接入方案见 [DETACH.md](DETACH.md)。

**现在能做的替代**：

1. 应用内桌面化：自由拖动、贴边、半屏、最小化成悬浮球（待做）。
2. 需要真正的系统窗口时，只能向 DSH 提需求；插件侧预留 `detach` 接口，宿主支持后接上。

**另一个要修的问题**：之前拖窗口会带着整个 DSH 一起动。原因是浮层压在了 Electron 的窗口拖拽区上；现在给页面和窗口加了 `-webkit-app-region: no-drag`，拖拽只作用于游戏窗口。

## 6. 多窗口（已实现）

- 可以同时开多个应用内窗口：每个窗口独立位置、尺寸、吸附模式，点谁谁置顶。
- 打开方式：「新窗口」按钮、「⋯ → 浮动窗口」、双击舞台标题栏；连续打开会级联错位。
- 窗口之间互不影响；关掉某一个不会影响其他窗口，页面上显示「N 个窗口运行中」。
- 「全部收回内嵌」会关掉所有窗口，回到页面里的舞台。
- 窗口本身的开关不持久化（刷新即关），窗口的**模板尺寸/模式**会记住，下次开窗沿用。

## 7. 独立系统窗口

插件侧已留 seam：`apply` 时探测 `ctx.get('desktopWindows')`，有 `openPanel` 就调用，没有就回退成应用内窗口并提示。宿主侧的 API 提案见 [DETACH.md](DETACH.md)。

## 8. 层级

- 窗口在 `shell.overlay` 渲染，天然高于所有列；窗口之间用 `zIndex` 排序。
- 模态对话框（插件管理、设置）由宿主绘制，可能盖住游戏的窗口；这是预期行为，不抢焦点。
