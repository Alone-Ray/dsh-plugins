# 兼容面总表（进度记分卡）

> 口径：**✅ 已完成** = 代码 + 样例 + 在这台机器上注册成功；**🟡 已铺路** = 链路通了但没有外部实证；**❌ 未开始**；**⛔ 不支持** = 设计上不做。
> 这张表是「兼容到底要搞定多少方」的答案，随进展更新。

## A. 游戏形态（12 类）

| # | 形态 | 状态 | 证据 / 说明 |
|:--|:--|:--|:--|
| A1 | 自研 Canvas 2D | ✅ | 贪吃蛇 |
| A2 | 自研 DOM | ✅ | 2048 |
| A3 | 自研 WebGL | ❌ | 适配器能传 canvas，但没有 WebGL 样例 |
| A4 | 第三方单文件 HTML5（canvas 脚本） | 🟡 | `web` 适配器已实现，用自研打砖块验证；**没有接外部源码** |
| A5 | 第三方 DOM / CSS 游戏 | 🟡 | 走 `native` 的路径成立，2048 是自研样例；**没有接外部源码** |
| A6 | Phaser / Pixi / CreateJS 打包产物 | ❌ | 需要把引擎和游戏打成一个自包含模块 |
| A7 | Cocos / Laya / Egret 导出 | ❌ | 还要处理它们的资源加载和全局 shim |
| A8 | Godot / Defold / Unity WebGL（WASM） | ❌ | 体积、加载、内存都没验证 |
| A9 | Flash / SWF（Ruffle） | ❌ | 计划有，未实现；AS3 兼容率未知 |
| A10 | FC / GBA 等 ROM（EmulatorJS） | ❌ | 和 A9 同类，更远 |
| A11 | 微信小游戏 | ❌ | 需要 `wx.*` shim |
| A12 | URL / iframe 游戏 | ⛔ | 不允许 iframe，也不允许远程贴地址 |
